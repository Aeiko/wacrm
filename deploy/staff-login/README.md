# Staging CRM: HTTPS at the proxy, private HTTP to login-gateway

This local review candidate supersedes the dedicated gateway certificate proposal for this trial. Both public origins remain HTTPS: `wacrm-staging.sqkii.land` and `wacrm-api-staging.sqkii.land`. Dokploy keeps Let's Encrypt TLS at the proxy; Cloudflare Full (strict) is unchanged. The eventual target for **both exact staging routes** is `login-gateway`, port **8080**, scheme **HTTP**. Do not publish that port, target CRM/inspection directly, or attach the earlier upstream HTTPS transport references. No shared proxy defaults, DNS, or edge settings change because of this manifest.

## Private boundary

- Before enabling either route, provide a dedicated internal bridge containing only that designated proxy, CRM and gateway; configure its reserved addresses using `LOGIN_FRONT_NETWORK`, `LOGIN_PROXY_IP`, `LOGIN_CRM_IP`, and `LOGIN_GATEWAY_IP`. The bridge is precreated and external to Compose. **Do not use shared `dokploy-network` as this boundary.** Verify the proxy uses the intended source address and selects this network for these routes; do not give its peers addresses on this bridge. Only the gateway joins `LOGIN_UPSTREAM_NETWORK`. Verify both networks and exact endpoint membership after any recreation.
- On the new gateway namespace only, install `http-gateway-fence.nft.in` before handling credentials or enabling routes. The input rule limits HTTP to the designated proxy IP; the output rules permit only the private CRM, GoTrue and PostgREST address/port pairs. Install and verify under a reviewed startup guard on each recreation; this manifest does not install it. The app independently binds the 8080 listener only to the expected address, checks the actual socket peer and exact Host, and does not trust `Forwarded` or `X-Forwarded-*`. The gateway has no credentials for database, service role, or inspection. Plaintext is limited to the selected same-host hop; a compromised proxy or host remains in the trust boundary.
- CRM SSR keeps its baked `https://wacrm-api-staging.sqkii.land` and maps that name to the proxy's **private TLS** listener using `extra_hosts`. The URL, Host, SNI, issuer and Supabase cookie namespace are not rewritten. The proxy must present a verified certificate for the exact API hostname on its private path. `ca.pem` is a trust-only input for CRM (use verified trust material, never a private key; fixture CA only in local tests). No TLS-verification bypass and no direct or HTTP SSR fallback. The gateway no longer needs a certificate or private key.
- `LOGIN_GATEWAY_MODE` defaults to `disabled` (exit 78 before binding). Modes are `private-http-fixture-v1` and `private-http-staging-v1`, with exact respective host and anon-key checks. Supply preloaded exact image IDs for `LOGIN_CRM_IMAGE` and `LOGIN_GATEWAY_IMAGE` (the previous TLS gateway image is not compatible). `LOGIN_INPUT_DIR` contains only the matching public `anon`, the trust-only `ca.pem`, and `gateway/upstreams.json` (`owner` synthetic user UUID; `proxy`, `listen`, `crmIP`, `auth`, and `rest` private literal addresses). Fixture Auth/REST ports 19999/3101; staged Auth/REST ports 9999/3000. Neither `config` nor trial logging exposes credentials. Routes and permitted operations remain scoped to auth, dashboard and inbox reads; not inspection, signup, admin, Studio, public database or Meta.

## Verification and hold

The local Compose contract discovers just `crm` and `login-gateway` with or without profiles; port 8080 is container-only. The local HTTP fixture uses an owned Node HTTPS proxy and disposable GoTrue/PG/PostgREST. A real Chromium browser authenticated the synthetic owner, read dashboard/inbox data and retry-header requests, reloaded via SSR, signed out from the menu, and was denied protected routes. The direct CRM connection to port 8080 returned 403 even with a forged forwarding header, then failed at the kernel after installing the fence. After the fence, the owned forbidden upstream port was blocked and approved endpoints still worked. Anonymous REST, signup/admin/inspection paths and password throttling also checked. This is not evidence of exact Traefik or hosted routing behavior.

Before any deployment: review/build/preload the new ARM64 image, prove exact native Traefik wiring including private SSR TLS, verify origin-only ingress and rate limiting that cannot be bypassed, and disable credential-bearing logs on the scoped proxy path as applicable. The gateway's socket rate limit is now shared by requests from the designated proxy; it is only a private backstop, not a per-client public edge limit. Rollback closes both exact trial routes first, then stops the new trial services; preserve existing proxy, staging data and inspection configuration. No hosted change or route is authorized by this local candidate.
