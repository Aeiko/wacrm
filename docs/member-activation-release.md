SQL093 retains the encrypted staging credential only within the original deadline. Member Connect has a distinct activation gesture, following confirmation of the full number and destination. The server repeats token introspection and authoritative phone checks under exact SQL session/workspace state. The route accepts no browser-supplied credential, provider proof, server pins or workspace ID. `activation_abort` clears the staging credential without changing a committed binding; expired/revoked/stopped credentials are inaccessible and eligible for staged maintenance cleanup. The attempt remains sticky rather than accepting a replacement.

The host must compose `memberSignup` with a trusted `MemberReceiverReview`. Its exact target is app/partner/WABA/phone/full number; it must independently establish scope, a current subscription for the reviewed app and callback, and a functioning signed receiver with continuous lifecycle and stop coverage. It must not accept a browser assertion, a generic health response, absence of a stop, or a fixture callback as proof. SQL rechecks locks, stop evidence, membership/session, claims and exact workspace before insertion. No history intent, permission, role change, provider write, or reply is part of activation.

Do **not** enable the activation flag or mount a test verifier on the standing runtime. The application route does not currently install a real review adapter and therefore cannot expose activation. The exact same-origin `activate` command is validated in the existing member gateway lane. Do not widen ingress to make activation green: the current preselection receiver guard is not proof of managed delivery after binding. Also retain the private SQL090 capability, and rehearse the merged image with the scoped worker/receiver and gateway. Read back the actual provider token/subscription contract and lifecycle proof before enabling; no test phone pairing is needed for code review.
