# SQL093 member activation contract

Use the installed SQL090 restricted-schema RPC `member_signup_private.coexistence_member_signup(p_actor_id uuid, p_session_id uuid, p_account_id uuid, p_action text, p_payload jsonb)` from the trusted server. Never accept browser identity, server pins, encrypted credentials, or receiver attestation from the client.

`activation_read`, `activation_abort`, and `activate` take the exact JSON string keys `state`, `app_id`, `login_config_id`, `partner_id`, `waba_id`, `phone_number_id`. `activate` additionally takes `normalized_phone_number`; calling it attests that fresh read-only provider checks verified the exact app/WABA/phone/full E.164, credential, and existing receiver subscription/readiness. No provider mutation or history consent is implied or authorized. The trusted server must fail closed if readiness cannot be proven. The dedicated receiver verifies using its app-level setting; do not copy its verification token into tenant config.

`activation_read` returns `{status: "activation_ready", access_token, token_expires_at, normalized_phone_number}` only for the original confirmed actor/session/account/state and exact pins/tuple while eligible. `access_token` is the encrypted envelope, never a browser response or log field. `token_expires_at` is the provider deadline, not the shorter staging deadline. `activate` returns `{status: "activated"}` after the local transaction commits. `inspect` returns `linked` once activated. Existing denial statuses apply; retrying either action on the same still-current, connected binding returns `activated` without writing again.
`activation_abort` returns `{status: "activation_aborted"}` and clears only the staged credential; it does not release claims, clear the pending selection, or disconnect an activated config. Use it on a trusted provider/readiness rejection, never as a browser action. Staging credential access ends at the earliest of the launch, live session, or provider deadline. Existing `coexistence_staged_maintenance` scrubs inaccessible credentials in bounded batches; activation also clears staging in its commit. Keep maintenance scheduled. SQL090-only pending receipts never contained an activation credential and are not made eligible by this upgrade. A stale pending selection does not authorize another exchange or replacement.

SQL093 can run before or after the restricted runtime install without changing the RPC's schema or grants. Verify offline with `python -B supabase/ci/verify-coexistence-member-activation.py --baseline <reviewed-offline-SQL074-snapshot>`.
