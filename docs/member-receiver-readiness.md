# Member receiver readiness

The permanent Next route installs the backend review; the browser cannot pass any readiness value. A member flag alone is insufficient. Eligible workspaces get an unavailable response until the current installed receiver has a valid app-level review. The server rechecks that review before member commands and before and after the post-selection subscription lookup.

## Before any real phone gesture

The isolated release operator owns `/run/wacrm-member-readiness/app-routing.json`. Mount only this root-owned, non-writable receipt into the CRM, read-only; no credential or customer identifiers belong in it. `WHATSAPP_MEMBER_RECEIVER_RELEASE` pins the independently attested current receiver image digest; it does not enable admission. The strict receipt binds `appId`, `loginConfigId`, `partnerId`, exact `callback`, and `release`, with `messagesVersion`, `accountUpdateVersion`, `reviewedAt`, `expiresAt`, and the SHA-256 references `dashboardEvidence` and `lifecycleEvidence`. The verifier validates the receipt, not the underlying artifact contents: the publisher must preserve the evidence and must not create the receipt as a config bootstrap or from a fixture assertion. The record expires within 15 minutes; do not auto-renew it upon a health-check or synthesize either digest. Remove it if the receiver or provider settings change.

## Only after the user selects the number

The app re-verifies the exact assigned WABA and phone against the grant, then makes an authenticated server-only `GET /{WABA}/subscribed_apps` using the same checked SQL090 session and state. It requires one matching app in an unpaginated result and rejects a nonmatching override; it does not follow pagination or create subscriptions. No app-level receipt asserts this WABA-specific fact. If the selected WABA does not already have that subscription, explicitly provision it for the exact confirmed pair via the approved provider operation and re-read it before activation. Do not change an unrelated callback or invoke provider registration. A failure during operational review clears the staged credential when the original SQL session is still authorized; the staged deadline closes access even if the abort cannot be delivered.

Production does not inject a synthetic verifier. The disposable browser fixture may replace readiness and Graph transport only in its throwaway source copy. Deploy via the single coordinated release with the existing private SQL090 capability, never the public REST gateway or a full-image swap from this worktree alone.
